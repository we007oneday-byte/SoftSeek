## 2. 推荐实施顺序

### 批次 A：视觉底座与信息架构（预计 2～3 个工作日）

目标：先让 App “看起来统一”，但不改数据层，降低后续返工。

1. 建立黑白灰 design token：背景、表面、文字、分隔线、气泡、代码块、错误色；保留 Light/Dark/System 三模式。
2. 统一组件：按钮、输入框、卡片、列表项、对话框、TopAppBar、空态、错误条；移除业务页面里的零散颜色。
3. 替换 App 图标：处理 `SOFTSEEKLOGO.png` 为 adaptive icon 前景/背景/单色层；生成 mipmap 多密度资源。
4. 新对话页品牌位替换为简化 LOGO；统一图片加载的 ContentScale 与占位。
5. Navigation Compose 路由整理：聊天、通话、通话历史、设置二级页、更新公告、关于；统一转场。
6. 先做设置一级菜单骨架，不搬全部具体配置；二级页先放占位，避免一次改 1000 行 SettingsScreen。
7. 开屏动画：系统 Splash 结束后播放品牌 SK 线框动画，0.8～1.2 秒，支持跳过；只在冷启动播放。
8. 十套风格底座：`VisualStyle` 枚举 + 每套 `VisualStyleSpec`（light/dark 色板、圆角、留白、描边、阴影、导航样式）；先接主题、气泡、卡片、设置项，逐页替换硬编码样式。

### 批次 B：配置、Provider 与模型底座（预计 4～6 个工作日）

目标：解决“只填 Key”“自定义模型”“多离线模型”三个底层能力。

1. 抽象 `ProviderProfile`：
   - `type = OPENAI_COMPATIBLE / ANTHROPIC / DEEPSEEK`
   - `baseUrl`、`apiKeyRef`、`defaultHeaders`、能力矩阵
   - OpenAI 适配：`Authorization: Bearer`、`/chat/completions`、`data: ...` SSE
   - Anthropic 适配：`x-api-key`、`anthropic-version`、`/v1/messages`、`content_block_delta` 等事件
2. API Key 配置流程：
   - 默认“只填 Key”；provider 选择器可折叠为高级项
   - 若 Key 以 `sk-ant-` 开头优先识别 Anthropic；其余先探测 DeepSeek/OpenAI-compatible 的 `/models`
   - 探测失败不阻塞，落回手动 provider/baseUrl；明确提示“未能自动识别”
3. `ModelProfile` 持久化：模型 id、显示名、provider、上下文、最大输出、视觉/推理能力、默认档位；支持新增/编辑/删除/从远端导入。
4. 底部模型条：模型、思考强度、最大输出三控件；读取当前会话/默认配置；未配置 Key 时提供配置入口。
5. 设置页二级化：API 配置、模型管理、聊天默认参数、通话设置、记忆池、外观、数据、关于；使用独立 route + ViewModel。
6. Vosk 多模型：
   - 从单 `VoskModelSpec.SMALL_CN` 提升为 `VoskModelCatalog`
   - 每个模型独立安装目录、大小/SHA、下载状态、选中状态
   - 选择框：切换当前模型；删除模型目录/安装包；当前模型删除时回退
   - 先内置 small-cn、small-en 两个规格；大模型只展示不默认下载

验收：无效 Key/错误 baseUrl/断网/SSE 中断均有可读错误；OpenAI/Anthropic mock 服务单测；模型切换后通话实际使用新模型。

## 3. 关键技术判断

1. **共享元素转场**：Compose BOM `2024.10.01` 已有 `SharedTransitionLayout`，但跨 Navigation 目的地仍是实验性组合。建议页面级统一用 `AnimatedContent`，只给品牌 LOGO/头像等少数元素做 shared bounds；不追求每个页面都共享。
2. **下拉刷新**：`accompanist-swiperefresh` 已归档，建议使用 Material3 `PullToRefreshBox`，避免引入废弃依赖。
3. **Shimmer**：优先自研 Compose 刷光，少引一个库；Lottie 再用 `lottie-compose`。
4. **动画状态**：`StateFlow` 管“选哪个动画/是否加载/是否启用”，不管每一帧的 progress；逐帧 progress 放 `Animatable`/`Transition`，否则每帧回写 ViewModel 会掉帧。
5. **API 自动识别**：仅凭 Key 无法 100% 判断 provider（OpenAI 与 DeepSeek 都是 `sk-` 前缀）。采用“Key 前缀 + `/models` 探测 + 失败回退手动选择”，并把探测结果缓存。
6. **Anthropic TTS**：Anthropic Messages API 不提供 TTS；外部 TTS 先按 OpenAI-compatible 音频接口实现，Anthropic 仅做聊天协议适配。
7. **本地 TTS**：导入模型不是选一个文件就结束，需要模型格式、tokenizer、ONNX runtime、音色配置。建议本期先交付“系统 TTS + 外部 TTS”，本地模型导入做壳与试听，sherpa-onnx 真正接入另立子任务，避免拖垮 ZL-01。
8. **头像删除语义**：App 会保存私有副本；用户删除相册原图不会导致 App 头像消失，只有私有副本被删/损坏才回退默认。若要求“删原图就回退”，则只能保存 URI 并承担权限失效风险，不推荐。
9. **会话隔离**：先复用 `tags` 标记 `call`，避免 Room 迁移；若后续通话需要独立字段/统计，再升版本加列。

## 5. 已确认决策

2026-11-19 用户确认：第 1～3 项按建议执行，第 4～7 项按推荐默认执行。

1. **极简主题（默认）**：近白底、细线分隔、紧凑布局、深色主按钮；十套风格均可切换并持久化；错误/危险保留唯一红色语义色，其余走各自风格色板。
2. **API 配置**：接受“先选 provider 再填 Key”；Key 只填一次，baseUrl、模型列表、能力与默认参数自动填充；`sk-ant-` 优先识别 Anthropic，其余探测 OpenAI-compatible `/models`，失败回退手动选择。
3. **本地 TTS**：本期只做“系统 TTS + 外部 OpenAI-compatible TTS + 本地模型导入壳”；sherpa-onnx 中文模型接入另立子任务，不阻塞 ZL-01。
4. **通话会话隔离**：采用 `tags=call`，不新增 Room 字段/表；文字列表过滤 `call`，通话历史只看 `call`。
5. **头像回退**：保存 App 私有副本；相册原图删除不影响头像，私有副本缺失/损坏才回退默认头像。
6. **动画状态**：业务加载/选中状态走 `StateFlow`；逐帧动画进度用 Compose `Animatable`，不回写 ViewModel。

## 7. TTS 引擎选型评估（2026-11-19）

### 7.1 CloneTTS

- 仓库：`https://github.com/sipeter/CloneTTS`
- 产品定位：Android 本地离线 TTS、1～3 秒音色克隆、系统 TTS 接管、本地 HTTP API、骁龙 NPU 加速、中英混排分句。
- 优势：中文和通话场景匹配度最高；可直接作为系统 TTS 引擎；v0.6.5 起 HTTP 支持 OpenAI-compatible `/v1/audio/speech`；有 NPU 路径和成熟的分句/发音规则。
- 关键限制：GitHub 仓库目前只有 README 与 docs，1 个 commit，没有应用源码、没有 LICENSE；不能作为开源代码直接 fork 或内置进 SOFTSEEK。
- 可行接入方式：仅作为“外部已安装 TTS”使用——用户在系统设置把 CloneTTS 设为默认 TTS，SOFTSEEK 走系统 TTS；或用户在 CloneTTS 开启本地 HTTP 服务，SOFTSEEK 的“外部 TTS”填其本地地址。两条都依赖外部 App、后台保活和用户配置，不适合作为首版内置能力。
- 结论：**产品参考价值高，代码集成价值为零（当前无源码/无许可证）**；可列为“兼容的外部 TTS”，不作为 ZL-01 内置引擎。

### 7.2 NekoSpeak

- 仓库：`https://github.com/siva-sub/NekoSpeak`
- 产品定位：Android 离线 TTS App，Kotlin/Compose + ONNX Runtime + CMake/JNI，支持 Piper、Kokoro、KittenTTS、Pocket-TTS；MIT 应用代码。
- 优势：完整可编译 Android 工程；系统 `TextToSpeechService` 实现、`TtsEngine` 抽象、自适应流式缓冲、模型/音色管理都可参考；MIT 代码可复用（需保留版权声明）。
- 关键限制：
  1. 它是完整 App，不是可直接依赖的库；抽取引擎要搬 ONNX/JNI/CMake、G2P、模型资产和系统 TTS 服务，工作量大。
  2. arm64 APK 约 88MB、universal 约 135MB；内置 Piper Amy 约 63MB；叠加到 SOFTSEEK 当前约 70MB 的 APK 上体积不可接受，必须改为可下载模型包。
  3. 稳定版以英语/Piper 社区音色为主；中文能力主要在 v1.5.0 预发布（OmniVoice 600+ 语言，模型约 3GB，且 tokenizer 仍有已知限制），不适合当前通话首版。
  4. 许可证混合：应用 MIT，但 eSpeak-NG 为 GPLv3，模型为 Apache-2.0/CC-BY-4.0 等；若 SOFTSEEK 不是 GPL 兼容授权，直接打包 eSpeak 有合规风险。
  5. 仓库包含“celebrity voices”名人音色库，语音人格权/授权风险高；不应引入。
  6. `app/build.gradle.kts` 中硬编码了 release keystore 与密码，不能照搬其签名配置。
- 结论：**架构参考价值高，直接集成不合适**；只借鉴 `TtsEngine` 抽象、流式缓冲、模型管理思路，不引入整包。

### 7.3 SOFTSEEK 建议路线

1. ZL-01 首版只做三层：系统 TTS（默认）、外部 OpenAI-compatible TTS、本地模型导入壳。
2. 本地模型后续用 `sherpa-onnx` + 中文 Piper/VITS 模型（如 `zh_CN-huayan` 系列，模型包约 84MB，按需下载），不引入 NekoSpeak 整包。
3. 音色克隆后置，且只允许用户克隆自己的声音，加入授权确认；不做名人音色库。
4. CloneTTS 作为“兼容目标”：文档说明可把系统 TTS 切到 CloneTTS，或在外部 TTS 中填其本地 `/v1/audio/speech` 地址；不作为内置依赖。
